# ИС учёта комплектующих

Курсовой проект: **«Проектирование и разработка информационной системы для учёта и контроля движения комплектующих на складе»**.

Веб-приложение для учёта поступления, выдачи, возврата, списания, перемещения и инвентаризации комплектующих с разграничением прав для трёх ролей: **Администратор**, **Кладовщик**, **Руководитель**.

> 🔗 Демо: `https://<ваш-логин>.github.io/<имя-репозитория>/` (после публикации, см. ниже)

## Как опубликовать на GitHub Pages

1. Создайте на GitHub новый **публичный** репозиторий (например, `warehouse-app`).
2. Загрузите в него **содержимое** этой папки (так, чтобы `index.html` лежал в корне репозитория):
   - через сайт: *Add file → Upload files* → перетащите все файлы и папки → *Commit changes*;
   - или через git:
     ```bash
     git init
     git add .
     git commit -m "ИС учёта комплектующих"
     git branch -M main
     git remote add origin https://github.com/<логин>/<репозиторий>.git
     git push -u origin main
     ```
3. В репозитории: **Settings → Pages → Build and deployment → Source: Deploy from a branch**, ветка `main`, папка `/ (root)` → **Save**.
4. Через 1–2 минуты сайт будет доступен по адресу `https://<логин>.github.io/<репозиторий>/`.

Сервер, база данных и сборка не нужны. Локально можно просто открыть `index.html` в браузере (для графиков и шрифтов нужен интернет).

## Архитектура

GitHub Pages размещает только статические файлы (HTML, CSS, JS), поэтому серверная часть Flask + PostgreSQL из ТЗ реализована **внутри браузера** с сохранением всех правил:

| Требование ТЗ | Реализация |
|---|---|
| Таблицы БД (п. 6.5) | Те же 10 таблиц: `roles`, `users`, `categories`, `units`, `locations`, `components`, `operations`, `operation_details`, `stock`, `audit_log` (`js/db.js`). DDL для PostgreSQL — `docs/schema.sql` |
| Хранение данных | IndexedDB браузера (основное, транзакционное) + копия в localStorage |
| Транзакции «всё или ничего» | `DB.tx()` — документ, строки, остатки и запись аудита сохраняются в одной транзакции IndexedDB; при ошибке всё откатывается |
| Конкурентный контроль | Транзакции IndexedDB выполняются строго по очереди даже из разных вкладок: из двух одновременных выдач последней единицы проводится только одна |
| Проверка прав «на сервере» | Каждая функция слоя бизнес-логики (`js/api.js`) сама проверяет вход, активность и роль. Скрытие кнопок — не единственная защита: прямой адрес или вызов из консоли тоже блокируется |
| Хеширование паролей | SHA-256 с солью и многократным повторением (`js/lib/sha256.js`), пароли в открытом виде не хранятся |
| Экспорт в Excel | Собственный генератор XLSX (`js/lib/xlsx-writer.js`), без внешних библиотек |
| Графики | Chart.js 4 |
| Интерфейс | HTML5, CSS3, Bootstrap 5, JavaScript ES6+, шрифт Roboto |

> ⚠️ Данные хранятся в браузере конкретного пользователя: у каждого проверяющего — своя копия с демонстрационными данными. Для переноса данных есть резервная копия в JSON (*Справочники → Обслуживание*).

### Структура проекта

```
index.html               — единственная страница приложения (SPA)
css/style.css            — оформление
js/lib/sha256.js         — хеширование паролей
js/lib/xlsx-writer.js    — формирование файлов Excel
js/db.js                 — хранилище и транзакции
js/api.js                — бизнес-логика, права доступа, проверки, отчёты
js/seed.js               — скрипт инициализации БД и тестовые данные
js/ui.js                 — таблицы (поиск, сортировка, пагинация по 20 строк), окна, уведомления
js/app.js                — маршрутизация и каркас
js/pages/*.js            — экраны: главная, документы, склад, номенклатура, отчёты,
                           история, справочники, пользователи, аудит, профиль
docs/schema.sql          — схема БД в виде DDL PostgreSQL
```

## Возможности по ролям

**Администратор** — сводка по пользователям, справочникам и операциям за период; создание, изменение, блокировка пользователей, сброс пароля (при первом входе требуется смена); справочники категорий, единиц измерения и мест хранения (архивирование вместо удаления используемых записей); номенклатура; остатки, история, отчёты, журнал действий, экспорт в Excel; резервное копирование и проверка согласованности остатков. Складские операции не проводит.

**Кладовщик** — быстрые действия «Поступление», «Выдача», «Возврат», «Списание», «Перемещение», «Инвентаризация»; черновики и проведение документов (с подтверждением и сводкой «остаток до → после»); сторнирование; карточки комплектующих; список позиций ниже минимума; отчёты и экспорт.

**Руководитель** — аналитический дашборд (динамика поступлений и выдач, наиболее расходуемые позиции, распределение по категориям), просмотр номенклатуры, остатков, истории и отчётов, экспорт. Создавать документы и менять данные не может.

### Отчёты
«Текущие остатки» (по местам хранения и суммарно), «Движение комплектующего» за период, «Выдача по получателям/подразделениям», «Ниже минимального остатка» — с графиками по тем же фильтрам и выгрузкой в XLSX.

Проверки выполнены автоматически в браузере Chrome (Playwright), разрешение 1366×768 и планшет 820×1180.

| № | Проверка | Результат |
|---|---|---|

| 3 | Повторный артикул (в т.ч. в другом регистре) отклоняется | ✅ |
| 4 | Поступление 10 ед. увеличивает остаток на 10 | ✅ |

| 7 | Возврат увеличивает остаток; возврат больше выданного блокируется | ✅ |
| 8 | Перемещение 3 ед. меняет остатки двух мест, общий остаток не меняется | ✅ |

| 10 | Проведённый документ нельзя изменить или удалить; исправление — сторно | ✅ |
| 11 | История показывает автора, дату, тип, состав; действия администратора в журнале | ✅ |
